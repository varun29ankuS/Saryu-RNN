Every configuration reaches 1.000, including d=512 with nh=2 at tr/dh = 0.938, which is inside the

P1 FALSE. The nh=2 arm does not degrade with width. It does not degrade at all.
P2 true but uninformative, since every arm holds.
P3 unmeasurable: the trace cannot be shown to be operative when nothing varies with it.

The ONLY residue of the predicted effect is convergence speed: d=512/nh=2 needed 500 steps where
every other configuration needed 250. The endpoint is identical. A 5,864,681-parameter model with
the "wrong" ratio matches a 9,059,657-parameter model with the "right" one, on 35% fewer
parameters.

WHAT IS RETRACTED. trained_geometry.txt item 2: "dh grows with model width while nh stays pinned at
2, so LARGER MODELS GET MONOTONICALLY WORSE at directed relation. The quantity to hold fixed is the
RATIO nh/dh." Not true for trained models on this task up to d=512. nh does not have to scale with
dh, and the concern that the shipped 25M checkpoint sits at tr/dh = 0.957 in a failing band is
unfounded for state tracking.

CONSEQUENCE FOR SCALING. There is now no known ARCHITECTURAL obstacle to making this model wider.
The remaining obstacle is compute, which is the honest answer to "why are we at 2-4 layers".

AND THE SIXTH CONSTRUCTION TO FAIL AGAINST TRAINING. The bands used here came from
composition.txt, which measured them by construction. The list is now: the nh ladder, the key-bound
write, sign binding, wide-vector-beats-matrix, the orbit account, and this. matrix_decision.txt
already records that "constructions here verify the mathematics and have NO demonstrated predictive
value for what gradient descent finds". At six for six that is no longer an observation about a few
cases; it is a rule. A construction in this repository is a check on the algebra and nothing more,
and should never again be used to predict a trained outcome or to set a design rule.
