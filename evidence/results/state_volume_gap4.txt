P1 HOLDS, DECISIVELY. THE FACT IS IN THE MATRIX.
  Ablating the memory read at the query position only: 0.926 -> 0.086 and 0.957 -> 0.125.
  Ablating the transport at the same position: 0.926 -> 0.906 and 0.957 -> 0.945.
  A cost of 0.84 against 0.02. The accuracy gain in memory_on.txt is not "a bigger model does
  better" -- the answer is being read out of the matrix, and an accumulator that held nothing
  retrievable would lose nothing when zeroed. The mechanism written into model.py's comments is
  the mechanism actually operating.

  The mirror image is as sharp. With memory=False, ablating the transport takes 0.238 -> 0.000.
  Without a memory the transport was carrying the whole task, at 0.24.

P2 MOVED, BUT NOT IN THE WAY THAT WOULD SUPPORT "THE PATHS COMPOSE".
  Gate retention 1/g, layer 0 mean:  memory=False 3742, 5948  ->  memory=True 10583, 10357.
  It roughly tripled and it is consistent across seeds, so the transport's behaviour really does
  change when the memory is switched on. That is all P2 registered, and it holds.

  But the honest reading is NOT a division of labour. Retention of ~10,000 tokens on a sequence
  of length 14 means the gate has essentially stopped writing -- the measure is far past
  saturation and the state is close to frozen. Put that beside the ablation, where the transport
  contributes 0.02 of 0.93, and the picture is that the transport WENT QUIET rather than
  reallocated to tracking.

  Which is correct behaviour, not a fault: MQAR has no order structure to track. There is nothing
  for the transport to do here, so going quiet is the right answer. It also means THIS TASK CANNOT
  DEMONSTRATE COMPLEMENTARITY, only takeover. The autocorrelation supports the same reading --
  the trained memory read is now LESS autocorrelated than the transport (0.327 vs 0.619 at lag 8),
  the reverse of the untrained run, because the memory is actively erasing and rewriting while
  the transport sits still.

STILL UNTESTED, and now with a clear specification. Complementarity needs a task that requires
BOTH an ordering and a set of facts -- where the answer depends on which fact was stored AND on
the order things occurred. Every task in this repository isolates one axis. Until such a task
exists, "the transport tracks while the memory stores" is a design intention supported on one
half and untested on the other.
